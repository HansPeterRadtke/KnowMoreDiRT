# KMD: Factual revisions, provenance-scoped truth, and independent checking — 2026-10-25

This analysis continues the owner's October 17–18 original recorded research question: *Can a knowledge-gathering agent derive genuinely new valid conclusions and independently falsifiable hypotheses while distinguishing source statements, opinions, false source claims and changing context?* It does **not** replace that with a software-implementation assignment or declare DRT/DRS the predetermined answer. Prior real PMB, SciFact, ContractNLI, HotpotQA and OPERA/Swanson investigations remain part of the evidence ledger. Original three actor/identifier failures `hrq086`, `hrq087`, `hrq089`, the additional source-context failures and all previous negative models remain unmodified.

## Original independent scientific evidence, acquisition and source interpretation

The source is Schuster, Fisch and Barzilay, [*Get Your Vitamin C! Robust Fact Verification with Contrastive Evidence*](https://aclanthology.org/2021.naacl-main.52/), NAACL 2021, DOI [10.18653/v1/2021.naacl-main.52](https://doi.org/10.18653/v1/2021.naacl-main.52). Their independently developed VitaminC dataset deliberately extracts pairs of Wikipedia source passages surrounding *factual revisions*, with each human-constructed claim being supported, refuted or insufficiently evidenced by a **specific version** of a paragraph. The creators' original code repository is [`TalSchuster/VitaminC`](https://github.com/TalSchuster/VitaminC), read at Git `eb532922b88b199df68ed26afeb58dca5501b52f`. The unchanged author dataset test split was read from publisher [`tals/vitaminc`](https://huggingface.co/datasets/tals/vitaminc) at Git revision `be6febb761b0b2807687e61e0b5282e459df2fa0` (original reuse **CC BY-SA 3.0**). The original file is on research-only Raspi `/data/tmp/kmd-vitaminc-original-test-20261025.jsonl`, SHA-256 **`7ad1808dbc30c62e0a1427a53022d0dfaff668a1fde3c4b612a2d266edd753ad`**, **55,197** original test text-pair records; it was neither rewritten nor committed wholesale. Every derived case ID and input-text SHA-256 remains linked to the original untouched rows.

The publisher's test includes **34,481 `revision_type=real`** author-recorded claim–evidence pairs and **20,716 `revision_type=synthetic`** records. These groups must remain separate: a synthetic revision is not independently observed Wikipedia history. The real subset contains **11,308 transition `case_id` groups**: 5,995 four-row, 5,186 two-row, 126 one-row, and one three-row group. The strict source-only structural criterion below excludes a rare nonregular four-way group and retains **5,994 complete real four-way revision groups**. Each selected group contains *two different claim strings crossed with two different source evidence strings*, with every claim appearing in both source variants. A `wiki_revision_id` identifies the underlying Wikipedia change, but **the downloaded test does not provide the precise valid-as-of timestamps of both passages or an independently certified current-world truth**. Treat each passage as version **A** or **B** of the same original source transition. Neither the entire group nor one later observed evidence paragraph may be silently promoted into an unqualified present-tense real-world fact.

## A large source-version-scoped reasoning result without manually supplied DRS

The source metadata-only analysis used **all 5,994 eligible real four-way groups**, equivalent to **11,988 distinct original claim strings each paired with two evidence versions**. The published original human evidence labels differed between two versions for **11,958 of 11,988 claim pairs** (**99.75%**). This was overwhelmingly intentional: the benchmark was designed to select changes that alter factual support; therefore **it does not estimate the prevalence of fact-altering changes in arbitrary Wikipedia edits or real news**. The changed label combinations were **9,862 `SUPPORTS`/`REFUTES`**, **2,082 `SUPPORTS`/`NOT ENOUGH INFO`**, and **14 `REFUTES`/`NOT ENOUGH INFO`**; only **30** claim-version pairs retained the same source label (26 support/support and 4 refute/refute). Every number comes from the original author labels and original unchanged source IDs, not from language-model judgment.

This yields a simple mathematically valid deduction **conditional on the original label definitions**: any system that represents a claim with one unqualified truth label and must assign the **same label across both source versions** cannot match both original human annotations when their labels differ. Even granting an *oracle* choice of that one label, such a version-blind strategy has an absolute best possible **50.125% simultaneous original evidence-label accuracy** across these selected four-way records. **This is an information-loss impossibility bound, not the accuracy of a practical implemented baseline, not DRS advantage and not evidence that the current world changed.** It follows from version identity being discarded when the question is specifically about support from different passages. The connection to the owner's original dream/quotations issue is structural: **source version**, like **world scope, speaker scope or quoted hypothetical scope**, changes the domain within which a proposition is being evaluated.

A strict `REFUTES` annotation on a source passage is not logical proof of its *actual real-world falsehood*; a `NOT ENOUGH INFO` annotation is explicitly **not** a proof of its negation. Similarly, two pages that say otherwise incompatible numbers may not contradict each other if the statements apply at distinct dates, locations, populations, or revision stages. Source-specific textual support and independent empirical validation are different questions. The original source confidence comes from published independent human annotations; the evaluator does **not** have new sensor data about any of these Wikipedia subjects. A live news article's correction history presents the same issue. A single source with a changed figure should be represented as a historical revision lineage, not as two independent corroborations or a simultaneous contradiction.

## Actual source-sensitive model inference on 2,800 frozen real inputs

`research/devtests_drt_reference/vitaminc_versions_20261025/freeze_real_revision_pairs.py` froze **700 original complete real revision groups**, **2,800 original claim–evidence inputs**, before model calls, selected by deterministic SHA-256 of original `case_id` *without reading the human support/refute labels*. The exact original group/source/page/revision identifiers and pair hashes are in `frozen_real_revision_source_only_20261025.json`, immutable SHA-256 **`a6c6fca2dd5de8674606c8496c7e6fb1918321ee16cf815cfe5d7ec2fdd9ed7c`**. The sample was selected structurally (original `revision_type=real`, exactly two unique claims and two unique passage versions), not cherry-picked for a model's failure or success.

An independently pretrained off-the-shelf SNLI/MNLI cross-encoder, `cross-encoder/nli-MiniLM2-L6-H768`, original revision `b95119ce93d3e065de6214e38cd4a97b0f2f2c6d`, was used for **one prediction per original claim–evidence pair**, not given human labels or a guessed true version. Its original ONNX quantized model SHA-256 is `449024a8711a3e655cad410cb2192158f9897fc2a32b65dbb817922351150db7`, with author label mapping contradiction/entailment/neutral to `REFUTES`/`SUPPORTS`/`NOT ENOUGH INFO`. It ran isolated on Raspi CPU only, two threads with reduced priority, 256-token original passage+claim pairs, no GPU or shared model/production disruption. The exact first-run probabilities, source input hash, model revision, tokenizer input length and truncation flags are checkpointed in `raw_source_version_nli_predictions_20261025.jsonl`. The original human label was read **only after all 2,800 first-pass predictions were complete** by `score_real_revision_contrast.py`.

The independent model agreed with the author source-specific text-evidence label in **1,136/2,800 = 40.57%**. On the selected **1,400 same-claim, two-version pairs**, original human evidence labels changed in **1,396**. The model changed its label between source versions in only **530** pairs, correctly flagging 529 true label changes and producing one false flip. Consequently it **missed 867 required changes**; change-detection recall was only **37.89%**, even though its observed flip precision was **99.81%**. It classified both original source versions correctly for only **282/1,400** same-claim pairs (**20.1%**). The original sample's label balance was **1,402 SUPPORTS, 1,150 REFUTES and 248 NOT ENOUGH INFO**; the generic NLI model overproduced NOT ENOUGH INFO (**1,373** predictions) and predicted SUPPORTS 757 times and REFUTES 670. Only **four of 2,800** inputs were truncated by its original 256-token budget, ruling out source truncation as the main explanation of the wrong pair labels. The complete original model confusion matrix, group-bootstrapped change prevalence, source-pair identities and negative cases are in `human_gold_revision_contrast_results_20261025.json`.

This is **meaningful negative evidence against treating generic NLI scores or repeated model agreement as correct fact revision tracking**. It is not evidence that every Wikipedia claim is truly supported/refuted in reality, or that every NLI model will exhibit the same failure. The original 2018–2021 Wikipedia training domain and test data are public, so pretrained model contamination cannot be ruled out. The sample was selected before gold analysis, but the evidence genre was intentionally contrastive, the evaluation reuses the authors' original test and this is not a complete cross-document production KMD integration.

## Scientifically established alternatives and complementary tools

- **Bitemporal source-version and provenance tracking** separates **when a statement was valid or applied in the world** from **when the database learned or stored that statement**. These values must be independently known, not invented from an opaque revision identifier. The original VitaminC data lack reliable per-version valid-time timestamps, so the honest representation retains the version transition ID, the evidence-variant hash and `as_of_time=unknown` rather than fabricated chronology. Original source text and the old assertion remain addressable after later revisions.
- **W3C [PROV-O](https://www.w3.org/TR/prov-o/)** provides interoperable derivation, source identity and revision links (`prov:wasRevisionOf`), distinct from quotation (`prov:wasQuotedFrom`) or direct measurement (`prov:hadPrimarySource`). It tracks what was derived *from what*, rather than deciding empirical truth or whether quoted fictional material actually happened.
- **Justification-based truth maintenance**, introduced by Jon Doyle in [*A Truth Maintenance System*, Artificial Intelligence 1979](https://doi.org/10.1016/0004-3702(79)90008-0), records reasons that support assumptions and conclusions and permits retraction or re-evaluation when assumptions become invalid. A new source version can invalidate a *derived current assertion* while retaining the historical source and the reason the previous assertion was once considered plausible. It does not establish that one side of a disagreement is objectively true.
- **Provenance semirings**, Green, Karvounarakis and Tannen, [*Provenance Semirings*, PODS 2007](https://www.cs.ucdavis.edu/~green/papers/pods07.pdf), annotate database-derived answers by their originating input records; this supports auditable multi-premise derivations and later source replacement, but an algebraic proof about database tuples does not validate original extracted natural-language propositions or independent biological facts.
- **Formal DRT/DRS and qualified logic** remain relevant for negation, conditional antecedent/consequence, referent and embedded speaker/world relations. The separate original PMB gold study showed published automatically generated neural DRS can capture hidden negation targets better than simple word matching on some linguistic sets, while real source-sentence errors in predicate roles and scope remain. An additional *actual KMD v5* test using Qwen2.5-1.5B produced **7/7 syntactically valid JSON, 0/7 accepted by the actual semantic validator**. Therefore attaching a DRS box to a revised Wikipedia paragraph cannot by itself establish that its extracted factual content, source version and applicable time are correct.

**Original owner's scientific question remains open beyond these source-level findings:** A reliable KMD research system must separate model-stated hypotheses, given premises, causal mechanisms and independently adjudicated discoveries. The historical Swanson fish-oil/Raynaud example generated a testable cross-literature conjecture later investigated clinically, but the outcome did not prove the viscosity mechanism. The original OPERA/ICARUS case illustrates independent physical evidence overturning a once-reported anomaly under precise experimental conditions. The VitaminC experiment adds **real source-revision evidence** that a single factual statement cannot safely be consolidated across versions. These are different stages—retrieval, scope extraction, logical deduction, empirical verification—and neither a single formal DRS parser nor many agreeing language-model outputs independently proves a novel scientific proposition.

A future matched evaluation must independently test a **larger actual KMD DRS parser versus a versioned provenance/neighbor/source-identity/temporal record system on exactly the same source passages**, tracking the *specific source variant and as-of-time*, quoted/dream/conditional scope, actor identity, evidence span and failed extractions. Exact source-conditioned downstream answer correctness and cost matter more than how many DRS structures parse as JSON. No such production-scale matched evaluation has yet succeeded; no truly novel laboratory result was generated in this historical study.

This report preserves prior results and source hashes; no original gold, production code, other agents' worktrees or source-bearing files were changed. The contrastive specialist-model follow-up, if evaluated, must be reported as a **post-hoc model-choice** test with its own frozen predictions, not a preregistered direct cause-of-improvement claim.
