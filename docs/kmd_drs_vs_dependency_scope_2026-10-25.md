# KMD: automatically extracted DRS semantics against a source-only syntactic baseline — 2026-10-25

This research continues the original owner's recorded question, **not** an invented implementation mandate: does an explicit DRT/DRS representation provide correct context-sensitive knowledge unavailable from original source, neighboring text, source metadata and simpler syntax/identity links? The [October 25 source-scope validation](kmd_drs_scope_content_validation_2026-10-25.md) showed that an actual specialist neural DRS parser **recognizes** negation much more often than it **places the correct original predicates** within that negation. This continuation adds a real independently pretrained **non-DRS source-only parser** measured on the identical original human semantic gold, rather than contrasting DRS with only one English regex. Research scope remains **limited to sentence-level source semantics**. Nothing here proves deployed full KMD DRS superiority over provenance-plus-neighbor, cross-document identity and dreaming, or valid new scientific discovery.

## Original independent published source and frozen input controls

Original [Parallel Meaning Bank 3.0](https://github.com/RikVN/DRS_parsing) author-corrected clausal DRS gold, **898 test** and **885 development** naturally occurring English sentences, was read unchanged from `RikVN/DRS_parsing@190838f9adea2af616eb76156d2e66c8565a6c6e`. The actual published automatic DRS parser output was read unchanged from `RikVN/Neural_DRS@81bcb26dfcc08f0da999cc7beaa2952f8820860c`, precomputed `bert_char_1enc/output1.txt` of each split. This is the BERT-plus-character DRS parser family described by van Noord et al., [*Character-level Representations Improve DRS-based Semantic Parsing Even in the Age of BERT*](https://aclanthology.org/2020.emnlp-main.371/), not a model run generated for this report. The human-corrected source, gold structures and original parser output remain read-only outside Git under `/data/tmp/kmd-pmb-{eval,reference}-20261024` on Raspi; literal SHA-256 checks cover the original three corresponding files per split. The old PMB category and full-scoped-predicate results, including negative outcomes, remain unchanged.

A **different, independently pretrained non-DRS model**—off-the-shelf spaCy English `en_core_web_sm` v3.8.0 with spaCy 3.8.3—was applied automatically to the **same source sentences**, without seeing human gold or any DRS schema. A fixed general English dependency rule maps negative markers to the governed verb/adjective, treats subject-level negative quantifiers, handles the common “anything but” exception and adjective+too+infinitive constructions, and then records an actual **candidate source negated lemma**. Its source-only predictions were frozen with evidence cue text/token indices and source sentence hashes in `frozen_spacy_dependency_predictions_20261025.json`, SHA-256 `fee8800b45fe36cff3c332262bfdcb34e6231ed7149697cc837c2115eebea1c3`, *before reading gold in the scoring process*. A stronger pretrained model `en_core_web_lg` v3.8.0 was run **after the first result was seen**, using the **identical frozen rules** and no label-specific tuning. Its separately frozen prediction SHA-256 is `f529470c7e49d04ab42c0e14604e7d0f4e80800e9feeb63eebc3fd03b790c6a5`. Thus it is explicitly a **post-hoc model-capacity robustness check**, not a fresh preregistered model-search win.

Both methods are scored against the **same** exact human-gold *multiset of VERB/ADJECTIVE predicate lemmas within the gold NEGATION box*, following any nested modal/negation boxes using the existing independent clausal graph reader. This intentionally excludes nominal negations, quantifier accessibility, role unification and some presuppositions. A sentence is gold-positive when at least one such gold scoped verb/adjective exists. Model DRS and source-only syntax each emit their actual predicted negated lemma multiset, without gold-provided operator or target scope. Gold-positive exact-match and term micro F1 are reported; false positive predicted targets on every other original sentence are counted separately. Human gold appears only in `score_dependency_vs_drs_negation.py` and its identical unchanged function used for the LG robustness; the predictor and frozen input never read gold. The gold source dataset has already been studied in earlier KMD rounds, so **do not call this a pristine untouched heldout benchmark**. Model pretraining exposure and unequal supervised semantic training cannot be ruled out; spaCy dependency parsing is also a learned, structured semantic-adjacent model, not just plain lexical retrieval.

## Measured identical-task results

| Original PMB split and metric | Specialized published neural DRS | Source-only spaCy SM | Source-only spaCy LG (post-hoc) |
| --- | ---: | ---: | ---: |
| **Test**: exact gold negated verb/adjective lemma set (77 gold-positive sentences) | **65/77 (84.4%)** | 56/77 (72.7%) | **60/77 (77.9%)** |
| **Test**: negated lemma term micro F1 | **0.897** | 0.813 | **0.848** |
| **Test**: false negated verb/adjective lemma predictions in 821 gold-empty sentences | 1 | 0 | 0 |
| **Dev**: exact gold negated verb/adjective lemma set (69 gold-positive sentences) | **65/69 (94.2%)** | 51/69 (73.9%) | 51/69 (73.9%) |
| **Dev**: negated lemma term micro F1 | **0.967** | 0.837 | 0.837 |
| **Dev**: false predicted target in 816 gold-empty sentences | 0 | 2 | 2 |

The **test** DRS minus spaCy-SM exact-match difference is **+11.69 percentage points**, paired bootstrap 95% interval roughly **+1.30 to +22.08 points**, with 14 DRS-only correct, 5 SM-only correct and 58 ties. The exact paired McNemar test has two-sided p≈**0.0636**, cautioning against overstating a small-sample exact-match result. Against the **stronger LG source-only baseline**, the test difference shrinks to **+6.49 points**, with 11 DRS-only correct, 6 LG-only correct and 60 ties. Its paired interval **−3.90 to +16.88 points** includes zero, with exact paired p≈**0.3323**. The external human-gold **development** split preserves a larger advantage: 17 DRS-only wins, 3 dependency-only, 49 ties and exact p≈**0.00258** (for both SM and LG); this is a *same-corpus development partition*, not independent genre replication. With only 77/69 gold-positive original sentences, and a lexical-lemma gold measure, these statistics cannot justify broad superiority of DRS over competent evidence retrieval.

The comparison is **not compute-matched**. The published specialist DRS parser was trained explicitly to generate PMB DRS clauses, while spaCy models were trained for general syntactic dependencies. The CPU source-only model ran locally, while the neural DRS scores reuse already-published predictions from their authors, so runtime/VRAM/call cost were not measured under identical conditions. The comparison is also **not a source- or neighbor-retrieval ablation**: each model saw one source sentence. It is a more competent *linguistic source-only alternative* for the narrower task of deciding which verb/adjective is negated. The separate 7,405 HotpotQA / 2,091 ContractNLI source-neighbor benchmarks measure retrieval but not parser-level DRS on the same documents. These are separate evidence categories, not scores to merge into one pipeline win.

## Concrete source-to-extraction counterexamples; same gold preserved

The large source-only parser sometimes handles actual material **better than the DRS** despite no DRS annotations: “Tom can't pronounce Mary's last name” → human gold negates **pronounce**, spaCy source-only predicts **pronounce**, published model DRS instead has negated **be**. Likewise, “I can't beat Tom at chess” → gold and spaCy scope **beat**, published DRS has no negated verb; and “None of his advice was very useful” → gold and source-only scope **useful**, published DRS misses it. Thus incorrect generated DRS should *never be treated as a compulsory authoritative replacement for the source text*.

Conversely, the specialized DRS is able to preserve additional negated scope predicates that the dependency-only extractor misses. For “I don't know where Tom's office is”, human gold and neural DRS contain **both know and be** in the relevant nested negation, while spaCy source-only predicts **know** alone. For “I can't afford to buy a laptop for my son”, DRS and human gold contain both **afford** and **buy**, while source-only predicts just **afford**. SpaCy LG corrected some source-only errors not corrected by the smaller general-purpose model; original examples and exact source sentence indices are retained in the scored JSON. These observations show why the **semantics of embedded clauses** can matter more than a single negation head—and why source-only dependency heuristics are a real, fallible comparator rather than an assumed adequate solution.

The earlier human-gold actor/role audit remains relevant: a parser can put a word inside the right negation scope and still assign *the wrong person* as `Agent` versus `Destination`. Extracting the correct predicate set is **necessary but not sufficient for truth-conditional equivalence**. This new lexical benchmark did not independently recheck anaphora, author quotations, dreams or historical supersession. In particular, a real report about a dream is evidence of **the dream occurrence**, not an assertion that events within the dream happened in the real world; a formal DRS box is useful only when its semantic contents and world link are independently grounded.

## Answer to the still-open original questions

**Measured limited result:** On a defined subset of real source sentences, a published automatically extracted DRS captures negation-governed predicates somewhat better than a source-only dependency model, with stronger evidence on dev and an inconclusive test difference against a larger source-only alternative. Both parsers make real original-gold errors. Therefore DRS can **encode useful nested semantic constraints**, but this result still **does not establish that deploying KMD's full DRS improves long-form multi-document answers over source-linked neighboring text plus lexical, entity and dependency features**. Such a test must control for gold document selection, model quality, prompt, latency, output budget, extraction failure, source offsets and identical human annotation, and include world, quote, author and time. Our prior isolated Qwen experiments showed invalid source-only DRS structures and source-polarity mistakes on real scientific/contract examples; no existing KMD actor-identifier gold was changed.

**Scientific new-insight result:** The source-backed Raynaud and OPERA examples and published Robot Scientist/FunSearch studies establish how new *hypotheses* and formally/experimentally tested conclusions can be generated. Nothing here establishes that KMD currently generates **genuinely novel independently verified scientific discoveries**. A SAT/SMT solver can validate consequences from a correctly extracted premise but cannot prove the original paper's premise is true; source independence, causal transportability and external measurements remain separate questions. A model's repetition or self-agreement is not independent evidence. These earlier conclusions remain unchanged by the source-negation parser ablation.

All experimental source file hashes, both frozen source-only models' raw cue traces, unmodified published neural DRS results and paired human gold evaluation are preserved as separate artifacts under `research/devtests_drt_reference/pmb_external_20261025/`. Scripts deliberately reject overwriting an already completed run. The source texts and model files are not recopied into Git. No production KMD implementation or original gold was changed, and no shared GPU/LLM service was used.

## Actual KMD production-schema feasibility on real scoped sentences (separate model trial)

To avoid substituting a hand-designed pseudo-DRS for the actual code, an isolated **small Qwen model was run with the unchanged installed KMD `build_chunk_drs_prompt`, `chunk_drs_json_schema(include_auxiliary_fields=False, source_id=..., constrain_stable_ids=True)` and `_validate_chunk_drs_payload`** on **seven real original PMB 3.0 source sentences**, not toy invented text. Source-only groups were frozen *before* inference using explicit regex cues, fixed SHA256 order and no gold DRS annotations: two negated sentences, two source-report/speech sentences, two conditionals, and one sentence describing what two people dreamed. The original source IDs, raw text, original sentence SHA-256, selection key and category are in `frozen_real_pmb_for_kmd_v5_20261025.json`, SHA-256 `4f500add47c30aa0b0463772a33b747bf909e1332fe9290a312d9698cb178d1b`. Because these PMB sentences were partly seen in earlier research and can have leaked into LLM pretraining, **do not call them unseen heldout model examples**.

The inference model was **`Qwen/Qwen2.5-1.5B-Instruct-GGUF` Q4_K_M** at pinned revision `91cad51170dc346986eccefdc2dd33a9da36ead9`, **isolated Raspi CPU** (two threads, nice 15, context 3,072, temperature zero, max completion 850 tokens), not the intended large Qwen KMD worker. The original production schema remained unchanged. The installed llama-cpp-python JSON grammar converter cannot read a Python `(?:...)` noncapturing-group pattern, so a **test-only regex syntax** adaptation from `(?:` to `(` was applied *solely to the local llama.cpp grammar representation*; both forms accept the same strings. **The canonical original schema and the actual KMD source/semantics validator were used unchanged for scoring**, without semantic repair or re-prompting. All original generation strings, source prompt and canonical schema hashes, source text and errors are preserved in `actual_kmd_v5_qwen_model_raw_20261025.jsonl`. The total observed generation time was **427.17 CPU seconds**; every one of seven first-pass outputs finished normally and contained complete JSON, without a single length-truncated or refused generation.

The independent audit `score_actual_kmd_v5_source_validity.py` checked **each** raw generated output against its **original JSON Schema via `jsonschema.Draft202012Validator`** and, separately, the original KMD `_validate_chunk_drs_payload` with the exact original source sentence. The results are in `original_kmd_schema_model_validity_20261025.json`:

| Original validation outcome | Count |
| --- | ---: |
| Complete JSON | **7/7** |
| Passes canonical KMD JSON Schema | **7/7** |
| Passes unchanged KMD semantic and source-grounding validator | **0/7** |
| Only root `b0` asserted box, no subordinate scoped box | **7/7** |
| Has at least one *source-grounding failure* | **5/7** |
| Has at least one declared-ref/identity or semantic KMD validator error | **7/7** |
| Exhausts completion token limit | **0/7** |

The errors are genuinely material, not stylistic. In the source sentence **“He's not jealous.”**, the extracted condition was a root-level `not` predicate and the model declared references to nonexistent `r0` instead of a subordinate negated jealousy proposition. The other original negative sentence **“My name isn't on the list.”** similarly generated only an asserted root condition, `has_name`. In both, the model also invented a `2023-01-01T00:00:00Z` temporal value absent from the source. The original **“According to a survey ...”** and **“Melanie said ...”** also produced only asserted root-level conditions plus a self-identity record; the *reported author scope* was lost. The dream report created no subordinate world box, and the two source conditionals had no subordinate conditional structures; one even contained a condition referencing itself as an argument. Original independently annotated PMB gold operator classes for each sentence are preserved for transparency but **are not asserted to be one-to-one the custom KMD schema's box vocabulary**. No original false output was silently repaired. The actual KMD validator correctly *rejected* all seven, preventing root assertions or invented dates from being accepted as validated source facts in this tested path.

This trial supports a narrower engineering/scientific result: **syntactically valid JSON constrained to the project's production schema is not a trustworthy source-grounded semantic representation**. A validator that checks reference integrity, subordinate scope and literal source support adds real safety beyond JSON Schema compliance. It does **not demonstrate 0% success for the intended 27B worker**, nor does it quantify DRT/DRS's theoretical validity, nor KMD's deployed extraction/QA behavior on a full document. The model is very small, the source sample is only seven, and grammar/budget/runtime differ from production. It is a meaningful additional **real-source negative operational feasibility check** alongside the larger independently measured PMB scope comparison, not a general model benchmark or proof that adding DRS can never help.
