# Reuse native KnowMoreDiRT facet extraction inside recursive summaries

On 7 November 2026, this isolated change connected the ORIGINAL KMD facet JSON schema to the complete-source hierarchy. The existing native content_representations table and content_chunks table remain the only database. The running source-only summary worker is not restarted until the new implementation has passed real-model and database tests.

The original FILE_ANALYSIS_SCHEMA, normalize_analysis, flatten_representations, facet strength vocabulary and representation-kind enum are imported directly from file_system_catalog.content_pipeline. No competing schema, file catalog or metadata index is introduced. Each recursive summarizer node has an optional normalized native analysis alongside its source-grounded document summary. The source span, original and derivative checksums, node ID, parent-child hierarchy, and summary text digest are preserved.

The existing model client is used with the original native schema but a stricter output reservation. Unlike the older AnalysisClient.complete, which grants all remaining context to generation, this adapter reserves a bounded number of output tokens before the source passage is packed. The constrained JSON response contains document_summary and facets in one model call. The active E5 model still requires summaries and individual keyphrase texts to fit its five-hundred-and-twelve-token embedding context. Failed length or schema checks cannot silently mark an incomplete original as complete.

Native source-linked storage uses one content chunk per generated summary node. It embeds and writes the summary plus the model-returned topic, keyword, keyphrase, entity, sentence or description representations. All representation kinds are flattened by KMD's existing normalizer, receive their own native vectors, and share the verified source chunk, source revision and summary-node link. The existing append_summary_rows transaction now accepts the original one-to-many representation structure while retaining its original SHA checks, foreign-key validation, idempotence, and storage limit. The old summary-only trees remain readable and are not overwritten.

Source search has a new opt-in with-facets mode which searches the verified native facet embeddings as well as the summary levels. The original batched summary-only ranking remains the default until stronger retrieval benchmarks justify changing it. Search logs identify the retrieval-engine variant for later evaluation. Summary status distinguishes summary vectors from additional native facet vectors.

A real Qwen call on the full twelve-thousand-character UX Research Methods Guide generated a source-complete summary, five facet topics and twenty keyword entries, including named UX study methods. The original KMD E5 model embedded all twenty-six representations. They were imported into the authoritative source-linked FileDB; SQLite integrity and foreign-key checks passed. A query about Card Sorting retrieved that guide in first position when facet retrieval was enabled; summary-only retrieval did not return it in the first five. This is evidence that keyword indexing changes recall, not proof that it always improves precision; the competing Card Sorting template may be preferable for some questions.

A separate real-model test on the complete seventy-thousand-character Rethinking the Reranker paper is initiated to verify that native facet output also survives source-level reduction and a parent summary. Synthetic multi-level tests already demonstrate source-linked keyword and keyphrase vectors at every recursive level, with identical source hashes and idempotent native writes. Actual full-book Qwen generation for the two-point-seven-five-million-character HCI textbook has also been started as a separate monitored service on the already loaded local Qwen model, using a conservative sixteen-thousand-token planning context. It remains an acceptance run until its full tree and search retrieval are verified.

No original file, model server, database or running worker has been replaced by these tests. All original-source content and query logs remain in the private Raspi data partition; only code and synthetic tests are committed.
