# Coder voice-model acceleration study, 8 November 2026

This native KnowMoreDiRT experiment tests the user's existing Qwen Coder voice-assistant model as a faster replacement for the currently running Qwen3.8 source-summary worker. It preserves the original Raspberry Pi Knowledge Library, original KMD FileDB, verified source revisions, multi-level summary tree and native keyword/keyphrase embeddings.

## Actual running models

Thor's existing llama.cpp server on port 14833 is Qwen3-Coder-30B-A3B-Instruct Q4_K_M. The model exposes 30.5 billion total parameters but only about three billion active parameters per inference token. Its advertised configured and trained contexts are both 262,144 tokens, discovered through the server's /v1/models endpoint; its live /props also advertises 262,144. The existing SWAAG foreground voice gateway uses exactly this model and endpoint. The server has **one inference slot**. The older indexing model is Qwen3.8-27B Q4 on port 14829 with a configured context of 16,384.

The model's actual context is discovered automatically by the existing original KMD AnalysisClient/LocalSummaryModel. A separate source-group cap of 16,384 is used for initial real indexing quality: a 262,144-token input condensed to a 130-word summary would potentially omit useful chapter-specific topics. This is a retrieval-fidelity choice, NOT hardcoding what the llama.cpp server actually supports.

## Measured source-grounded tests

The complete 12,642-character UX Research Methods Guide was checked against the current source-map and download ledger. Native KMD schema-constrained summary+facet generation was run with no production writes. Against twenty predeclared named UX methods actually present in the original source, the older Qwen3.8 Q4 output recovered all twenty, with twenty keywords, in 169.7 seconds. An initial Coder run took 133.44 seconds and recovered only six of twenty named methods, despite producing twenty generic keywords. A revised **domain-independent** instruction prioritized explicit names and detailed useful labels; it recovered all twenty methods, produced thirty-one keywords and eight keyphrases, and completed in **82.95 seconds**. The Coder model itself reported the full native 262,144-token context, while the source fit in one generation call.

A longer full original RFC 9866 source of 60,749 characters was processed by Coder in a single input group under the full native context, taking 140.66 seconds. It retained the named RNFD roles, states, control-message identifiers and several parameter names but omitted the numerical default consensus threshold value of 0.51. The previous Qwen3.8 summary-only hierarchical run needed three first-level calls plus one parent and took 155 seconds, while preserving that explicit value. This is a concrete warning that unrestricted large-context grouping can sacrifice rare source details; it is not evidence that the larger context always accelerates quality-preserving work.

All benchmark outputs and exact model timings are in the private Raspi search-audit/coder-quality-speed-20261108 folder. There are no user documents, source copies, model binaries, vectors or private query logs in Git.

## Final compact-output experiment and deployment choice

A W3C accessibility source canary was generated by Coder, but the
initial verbose facet prompt exhausted 2,400 output tokens and had
to retry using the existing strict prompt. The complete native result
was source-valid, included six topic facets and twenty keywords,
was embedded in the ORIGINAL KMD FileDB, and its source ranked first
for a relevant accessibility query. Its total generation time of
290.6 seconds demonstrates why a verbose-first prompt is not
sufficient for the speed objective.

A new optional compact native-facet prompt uses the ORIGINAL
FILE_ANALYSIS_SCHEMA and its normalizer but starts with the shorter,
source-faithful instructions that previously served as the fallback.
It explicitly requests every specifically named method or term in a
manageable source list, concise grouped keyword rows, and actual
numeric constants. On the same UX guide the Coder generated a
complete source summary and thirty native keywords in 86.97
seconds without a truncation retry, recovering eighteen of the
twenty gold named methods. The old Qwen3.8 run preserved all
twenty in 169.7 seconds. The two missed method labels were
'desirability studies' and 'usability benchmarking'; the shorter
summary used generic 'benchmarking' for one. This is a measured
detail-recall loss, not a proof of equivalent quality.

The selected rollout configuration therefore uses compact prompt
and conservatively bounded 16,384-token source groups while still
discovering the Coder's full 262,144-token context from llama.cpp.
The single-slot idle-admission gate waits for eight continuously
idle seconds before every uncached request and yields between calls.
No changes to the Thor voice server itself are planned. This is
**not** guaranteed voice-call preemption; a voice request arriving
during a long summary may still be delayed. The worker remains
rollback-able to the original Qwen3.8 endpoint and model profile.

## Shared voice model: real scheduling constraint

Coder is the existing foreground voice model. Its llama.cpp server runs with only one slot and does not support interrupting an active summarization request to answer a later voice request. The native KMD adapter now offers an optional **fail-closed idle-admission gate**. Before each uncached model request, it inspects the existing llama.cpp /slots endpoint and waits until the server is continuously idle for a configurable interval. Malformed/unavailable slot state cannot be treated as permission to submit blindly; waiting is bounded. The gate leaves an idle opportunity between KMD requests. It cannot preempt a KMD request after one has started, so a new voice request can still wait for that single request to finish. No Thor voice-service configuration was changed.

The KMD worker's model URL, advertised model alias, maximum generation tokens, and optional quality-specific context cap are now configurable on startup. It retains its singleton worker lock, the original KMD FileDB transaction guard, source-SHA checks, automatic retries, sequential LLM calls, resource limits and query logs. Qwen Coder native facet output uses the **existing** KnowMoreDiRT FILE_ANALYSIS_SCHEMA, normalization, and native representation kinds. The original summary-only behavior is unchanged unless a model profile is explicitly selected.

## Test status and rollout policy

Synthetic model admission tests exercise voice-busy wait, continuous idle acceptance, malformed-slot refusal, timeout, model context autodiscovery/cap, and source-specific numeric detail prompting. The entire existing native source-summary, store, search and worker regression suite is rerun before deployment. A real source-linked Coder canary on a W3C accessibility document checks actual native summary+keyword generation, embedding, provenance and retrieval in the original FileDB.

The active Thor voice model service must not be stopped or reconfigured to achieve indexing speed. Production model changes belong only in the KMD worker and its source-controlled Raspberry Pi unit. A source may be restarted at a verified completion boundary; incomplete attempts are not marked as finished. The benchmark does not yet justify a claim that the full library will finish within any specific number of weeks.
