# Factual version scope versus timeless claims — VitaminC originals, 2026-10-25

This work addresses the original owner's question: does a knowledge agent turn **historical source claims** into unqualified, falsely contradictory world facts, and can independent source evidence guide valid conditional conclusions? It is **not** a claim of a new empirical scientific discovery, nor a production KMD DRS benchmark.

The primary independent published dataset is [Schuster, Fisch and Barzilay, *Get Your Vitamin C! Robust Fact Verification with Contrastive Evidence*, NAACL 2021, DOI 10.18653/v1/2021.naacl-main.52](https://aclanthology.org/2021.naacl-main.52/), original code [TalSchuster/VitaminC](https://github.com/TalSchuster/VitaminC), publisher source `tals/vitaminc` at dataset Git revision `be6febb761b0b2807687e61e0b5282e459df2fa0`. The original **unaltered** `test.jsonl` (55,197 human/publisher annotated source claim–passage pairs) is held *outside Git* on Raspi at `/data/tmp/kmd-vitaminc-original-test-20261025.jsonl`, SHA-256 `7ad1808dbc30c62e0a1427a53022d0dfaff668a1fde3c4b612a2d266edd753ad`, original **CC BY-SA 3.0** license. Do not copy the whole copyrighted/attribution-required source into project code or treat its claim support labels as universal scientific facts.

Original test rows have original publisher `unique_id`, `case_id`, `wiki_revision_id`, `label`, `claim`, `evidence`, `page`, `revision_type`. The **real** revision subset is distinguished from a separate publisher `synthetic` subset; do not silently mix both as real-world edit observations. The `wiki_revision_id` is one original revision transition identifier, **not a dated validity interval for each old/new evidence variant**. The same `case_id` can contain four rows: two different claim statements crossed with two different source evidence versions, yielding four independently supplied source-specific label decisions. Each version must be a separate source snapshot; apparently opposite labels across versions do **not** establish incompatible premises at one world/time. The dataset still lacks an independent direct test establishing Wikipedia truth at all times.

`freeze_real_revision_pairs.py` selected structurally complete **5994 eligible real four-way groups** without looking at label: exactly two claim strings and two evidence strings repeated in a cross product, one source page/revision transition. It used a deterministic SHA256 of case ID to freeze **700 groups/2,800 original pairs** in `frozen_real_revision_source_only_20261025.json` (SHA256 `a6c6fca2dd5de8674606c8496c7e6fb1918321ee16cf815cfe5d7ec2fdd9ed7c`). Only original source IDs and source-input hashes are stored in Git; raw copyrighted evidence remains in the external untouched dataset. Original model predictions had not begun until this file was frozen.

`run_source_version_aware_nli_cpu.py` uses the unchanged off-the-shelf generic SNLI/MNLI model `cross-encoder/nli-MiniLM2-L6-H768` original revision `b95119ce93d3e065de6214e38cd4a97b0f2f2c6d`, quantized CPU ONNX SHA-256 `449024a8711a3e655cad410cb2192158f9897fc2a32b65dbb817922351150db7`, already installed at `/data/tmp/kmd-scientific-nli-20261024/`, two CPU threads, `MAX_LENGTH=256`, one automatic model decision per source version and claim, original label order `[REFUTES,SUPPORTS,NOT ENOUGH INFO]`. Inference **never accesses human labels** or uses Wikipedia version ID as a truth class. Batch outputs are checkpointed to `raw_source_version_nli_predictions_20261025.jsonl` with source UID, original pair SHA256, label probabilities, full input token count and truncation flag. No retraining, manual label repairing or repeated completed output is permitted.

`score_real_revision_contrast.py` requires **all 2,800 original predictions**. It then reads publisher original human gold exactly once, separately records (a) label changes for every structurally eligible **real** four-way group across the complete original test corpus, and (b) the frozen-model 700-group sample. It measures source-version-related label flips, paired model adaptability and wrong-source label reuse, independently of general knowledge. A *mathematical impossibility bound* from the original human labels says any system that assigns **the same label** to the same claim across two differently labeled source versions must be wrong for at least one version; this is **not** a practical classifier and must not be reported as operational accuracy. No inference conclusion is called universal truth. Original source/version IDs, pair hashes and label contrasts remain auditable.

Scientific alternatives and their limits: [W3C PROV-O](https://www.w3.org/TR/prov-o/) defines `prov:wasRevisionOf`, `prov:wasQuotedFrom` and generation/attribution, giving source identity and provenance but not truth by itself. [Doyle, *A Truth Maintenance System*, Artificial Intelligence 1979](https://doi.org/10.1016/0004-3702(79)90008-0) stores justifications for conclusions and supports nonmonotonic revision of assumed beliefs. [Green, Karvounarakis and Tannen, *Provenance Semirings*, PODS 2007](https://www.cs.ucdavis.edu/~green/papers/pods07.pdf) propagates database derivation/source annotations algebraically but cannot guarantee empirical correctness or independence. These techniques provide **direct alternatives/complements to DRT/DRS** for tracking source version/assumptions/causal evidence; none magically parses dream/quote scope or makes a scientific proposition true.

There is no fair original dataset production KMD `chunk-drs-v5` vs provenance-and-neighbor answer benchmark here; the earlier seven source-sentence small CPU Qwen full-schema trial remained **0/7 accepted by KMD semantic grounding** despite 7/7 valid JSON. Previous independent PMB comparisons show both trained DRS and generic syntactic alternatives are fallible, and the original `hrq086`, `hrq087`, `hrq089` identifier/source failures remain unaltered. Full research interpretations belong in the owning dated `docs/` report.
